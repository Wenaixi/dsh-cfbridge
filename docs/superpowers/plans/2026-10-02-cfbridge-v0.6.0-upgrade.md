# @wenaixi/cfbridge v0.6.0 升级实施计划

> **面向 Agent 执行者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 按任务逐项实现本计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 将 @wenaixi/cfbridge 插件从 0.5.0 全面升级至 0.6.0，引入基于 mtime 的高性能技能元数据缓存、可配置 Provider 优先级（rank）、开发态技能热监听（Reversible Watcher Effect）与增强型 Schemastery 配置，全面对齐 DSH 官方最新插件架构规范。

**架构：** 在 Provider 发现层接入 mtime 驱动的惰性缓存层以消除冗余磁盘 IO；在 `apply` 生命周期中采用 Cordis `ctx.effect` 纳管可选的技能文件变动监听器并广播 `skills/change` 事件；通过 Schemastery 声明强类型运行时配置与严格边界校验。

**技术栈：** TypeScript 5.9+, Node.js >= 22 (ESM), @deepseek-ai/cordis ^4.0.2, @deepseek-ai/dsh-skill, @deepseek-ai/schemastery ^3.18.2, yaml 2.x, node:test。

**规格：** 参考 DSH 官方插件开发规范（`dsh-plugin-dev`）八大硬规则、`references/services.md`、`references/config.md` 与现行 `CLAUDE.md`。

## 全局约束

- 运行时纯 ESM，Node >= 22；代码与注释严禁使用任何 emoji。
- 遵循 DSH 官方硬规则：所有贡献都是副作用，所有外部资源（监听器、定时器、句柄）必须包装在 `ctx.effect` 内并在插件卸载时完全释放。
- 配置一律导出同名 Schemastery Schema，严禁导出普通 JavaScript 对象作为 Config。
- 保持 Bundle Patch 只保留 Cloudflare MCP 与 `cfbridge` 两行，禁止恢复旧路由与多行 patch。
- 构建产物 `lib/` 必须随源码实时编译并提交。
- 本地提交使用原子化规范提交（`feat:`, `test:`, `docs:`, `chore:`）。

## Review Focus

1. **取消信号（AbortSignal）穿透**：当会话取消或超时时，带有 mtime 缓存检查的 `list()` 和 `get()` 必须第一时间响应 `throwIfAborted(options)`，绝不能因缓存命中而漏检信号。
2. **Watcher 资源泄露防范**：开启 `watchSkills` 时的文件系统监听器必须在 `ctx.effect` 返回的 disposer 中彻底关闭（`watcher.close()`），在插件卸载或热重载时不得遗留孤儿监听。
3. **缓存击穿与文件删除一致性**：当磁盘上的技能目录或 `SKILL.md` 被删除时，缓存必须同步失效，`list()` 不得继续返回已不存在的候选技能。
4. **并发与边界竞态**：短时间内多次并发调用 `list()` 时，mtime 缓存更新必须保持原子一致，避免 Map 迭代状态污染。
5. **Schema 向后兼容性**：新增的 `rank`、`cache`、`watchSkills` 配置必须带有合法的默认值，现存用户的 `cordis.patch.yml` 无需任何修改即可无缝平滑升级。

- [ ] **步骤 3：在 `src/cfbridge.ts` 中实现缓存逻辑**

在 `createProviderForTest` 闭包中建立：
```ts
type CacheEntry = { mtimeMs: number; candidate: SkillCandidate }
const cache = new Map<string, CacheEntry>()
```
在遍历技能目录时：
1. 先执行 `statResult = await stat(path)`；
2. 若 `cacheEnabled && cache.has(path)` 且 `cache.get(path)!.mtimeMs === statResult.mtimeMs`，直接复用已缓存的 candidate；
3. 若未命中或 mtime 发生变化，则读取文件、解析 frontmatter、构造 candidate 并写入缓存；
4. 若文件已不存在，清理该路径的缓存条目。

### 任务 3：实现开发态技能文件变动监听（Reversible Watcher Effect）

**文件：**
- 修改：`src/cfbridge.ts`
- 测试：`tests/provider.test.mjs`

**接口：**
- 消费：`node:fs: watch`, `Context.effect`, `Context.emit`
- 产出：当 `config.watchSkills === true` 时，文件变动自动去抖动触发 `ctx.emit('skills/change')`，并在插件卸载时自动关闭 watcher

- [ ] **步骤 1：编写失败的测试**

```js
test('apply mounts file watcher and cleans up on dispose when watchSkills is true', async () => {
  const root = await fixture()
  const events = []
  const disposers = []
  const mockCtx = {
    logger: { warn() {}, debug() {}, info() {} },
    skills: { registerProvider: () => () => {} },
    on: () => () => {},
    emit: (evt) => events.push(evt),
    effect: (fn) => {
      const d = fn()
      disposers.push(d)
      return d
    }
  }

  apply(mockCtx, { skillDir: root, providerName: 'cfbridge', watchSkills: true })
  assert.equal(disposers.length, 1)
  // 调用 disposer 确认无报错
  for (const d of disposers) d()
})
```

- [ ] **步骤 2：运行测试，确认其失败**

运行：`node --test tests/provider.test.mjs`
预期：FAIL，因为现有 `apply` 尚未支持 `watchSkills` 监听器。

- [ ] **步骤 3：在 `src/cfbridge.ts` 中实现可逆文件监听**

在 `apply(ctx, config)` 的 `ctx.effect` 中：
```ts
ctx.effect(() => {
  const disposeProvider = ctx.skills.registerProvider(() =>
    createProviderForTest(skillDir, providerName, ctx.logger, config.rank ?? PROVIDER_RANK, config.cache ?? true)
  )
  const disposeListener = ctx.on('skills/change', () => ctx.logger.debug?.('[cfbridge] skills catalog changed'))

  let watcher: any
  if (config.watchSkills) {
    try {
      let debounceTimer: NodeJS.Timeout | undefined
      watcher = watch(skillDir, { recursive: true }, (_eventType, filename) => {
        if (!filename || filename.endsWith('.md')) {
          if (debounceTimer) clearTimeout(debounceTimer)
          debounceTimer = setTimeout(() => {
            ctx.emit?.('skills/change')
          }, 150)
        }
      })
    } catch (e) {
      ctx.logger.warn?.('[cfbridge] failed to initialize skills watcher: ' + String(e))
    }
  }

  return () => {
    if (watcher && typeof watcher.close === 'function') watcher.close()
    disposeListener()
    disposeProvider()
  }
})
```

运行：`npm run build && node --test tests/provider.test.mjs`
预期：PASS，所有测试均通过。
