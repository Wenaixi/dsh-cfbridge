# cfbridge 0.3.0 全量 Vendoring 历史实施计划

> 状态：历史方案记录。当前实现以 0.5.0 单一 TypeScript SkillProvider 为准。

## 历史目标

- 解释 DSH 的 Bundle、Agent Preset 与动态 Cordis Plugin 三种形态。
- 将 13 个官方 Cloudflare SKILL.md 快照随包提供，使 cfbridge 共提供 14 个按需发现的技能。

## 当前架构对照

- 历史方案曾为 13 个快照各生成一个 src/<name>-skill.js wrapper，并把 Bundle patch 从 1 个技能行扩为 14 行。
- 0.5.0 已删除这些 wrapper，统一由 src/cfbridge.ts Provider 扫描 skills/*/SKILL.md；Bundle patch 现在只保留 mcp-cloudflare 与 cfbridge 两行。
- 历史 vendored 快照仍保留在 skills/，由 Provider 在索引阶段读取 frontmatter，在 get() 阶段惰性读取正文。

## 历史形态说明

### DSH Bundle

- 通过包根 cordis.patch.yml 与 package.json 的 dsh.bundle.patch 加载。
- 安装到 profile 后对所有会话生效。
- 当前版本包含 1 个 Cloudflare MCP 行与 1 个 Provider 行。

### Agent Preset

- 历史 preset 放在 $DSH_HOME/.agent-presets/<id>/，需要会话显式选择。
- 不应与 Bundle 同时注册相同的 mcp__cloudflare__* 工具。
- 旧 preset 仅用于迁移，使用 npm run migrate:from-preset -- --yes 清理。

### 动态 Cordis Plugin

- 仅适合临时探针或演示，生命周期随运行实例结束。
- 不作为持久技能分发方式。

## 历史文件树

```text
package.json                 # 历史 0.2.0 -> 0.3.0；当前 0.5.0
cordis.patch.yml             # 历史 1 行 -> 14 行；当前 2 行
src/cfbridge.ts              # 当前 Provider 入口
skills/<name>/SKILL.md       # 14 个快照
scripts/sync-vendor-skills.js
```

## 迁移结论

- 不恢复旧 wrapper，也不把 14 个技能重新拆成 14 个 patch 行。
- 修改 Provider 或技能文件后，运行 npm run build、npm run typecheck、npm run test 与 npm pack --dry-run。
- 仅使用临时 DSH_HOME 做安装验证，不写入现有 web profile。
